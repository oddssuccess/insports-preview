現有頁面的分工與來源依據

依 BetLogics 工作目錄的 services/office/web/src/app/layouts/standard/menu.ts 與 app.routes.ts 核對；以下來源路徑皆相對於 betlogics/services/office/web/src/app/。這份草稿核對的是頁面與導覽，不代表已驗證正式環境的功能完整性。

目前只有 Sports、Tournaments、Competitors 連到本 repo 既有的畫面；其餘為位置示意。Provider › Betting 在現有模式保留作為對照，它是系統管理者的驗證下注工具，並非玩家注單清單。驗證外部下注不屬於本次 InSports 賽事產線；取得資料帳號只用於讀取資料（R03-04），因此已採用的第一階段模式移除它。三個模式都只處理賽事，冠軍盤另行規劃。預設顯示已採用的第一階段選單；完整投注流程的 Planned 入口是後續規劃，不表示功能已完成。

新增與不新增的決定

項目建議原因與完成條件
Feed Monitor第一階段已加入主入口，標示 Planned；功能頁待實作。需能依客戶與資料類別查看 API／串流的供應狀態、最後送出時間與資料版本、延遲、錯誤、斷線及補同步情形，並連回相關賽事或 Feed Tenant。伺服器成功送出與客戶確認收到要分開；沒有客戶確認機制時不得宣稱已收到。實際可觀測欄位與門檻待定。
Pipeline沿用 Connectors 的次頁。頁面已存在。若值班使用頻率高，可提升為主選單捷徑；這是導覽調整，不是新能力。
Dashboard / Attention補齊既有頁面與摘要資料。pages/dashboard/dashboard.ts 明示畫面骨架；layouts/standard/menu.ts 的 Attention 數量與等待時間仍為固定範例。應接上真實的處理狀態與頁面捷徑，避免再建重複的總覽或審核入口。
Audit Log可選改進，暫不新增主選單。已有每位使用者的 Activity 與業務紀錄。若事故追查常需跨使用者、賽事或設定搜尋，再於 Users & Permissions 增加共用檢索入口；底層稽核不是從零開始。
Sources / Accounts / Mapping Tables不另建獨立主入口。沿用 Provider Settings、Commentary 與既有對應頁。InSports 規則有差異時，調整其頁內內容，避免兩個入口管理同一件事。
Provider › BettingInSports 第一階段模式移除。它驗證供應商下注，不是 InSports 的玩家下注流程；取得資料帳號不得下注（03 的 R03-04）。

本次採用的是導覽方案。Feed Monitor 的功能頁、資料介面，以及 Dashboard／Attention 的真實數據串接，仍列為實作工作；本稿不改動 BetLogics 的應用程式或 InSports 的業務規則。

完整投注流程規劃：玩家下注到派彩

「完整投注流程（規劃）」模式已列出下列入口，供整體導覽檢視。接受狀態與追查放在 Bet List；Monitoring 同時涵蓋監控參數、趨勢與曝險；Reports 內提供投注額與 GGR 檢視。功能頁在對應 PRD 明確後實作。

建議群組與入口要補上的工作需求依據與狀態
Bet Operations › Bet List查看真實玩家的注單、等待／確認／拒絕狀態與原因，從同一筆注單追查接受流程及錢包扣款邊界；不另設重複的 Acceptance 主入口。06：R06-18、R06-19、R06-20；頁面分工為建議。
Settlement › Bet Settlements / Payout Exceptions由投注項結果追到注單結算、取消、重新結算，以及派彩失敗或扣回的注單狀態；實際錢包入帳仍由整合端負責。07 的目的與範圍；規則仍是骨架，不能先指定重試或強制入帳操作。
Risk › Monitoring / Review Queue / Rules查看監控參數、趨勢與曝險，處理警示與人工佇列，維護基本條件與觸發條件。09 概念草稿；R06-10、R06-17 提供限額與人工標記的邊界。
Distributors › Settings經銷商的偏好、價格、模板、開關與繼承／覆寫。此入口依經銷商角色的權限提供，並不授予 Ops 任意修改所有經銷商設定的權限；Feed Tenants 仍負責 API 客戶權限。10：R10-01 至 R10-04；12：R12-08。
Reports / Settings › Exchange Rates投注額、GGR 與經銷商層級報表；依營業日查看及覆寫匯率。11 的目的與範圍、R11-01；報表詳細欄位待撰寫。
Bet Operations › Cash Out提供提前兌現紀錄與失敗狀態的入口；注單可否提前兌現依玩法設定與 08 的規則決定。詳細規則待補完，不預先加入人工強制兌現操作。08 的目的與範圍；規則仍是骨架。

待確認事項

  • Feed Monitor 的資料來源、可觀測欄位與客戶確認機制，以及何種情況需要人工處理，待補入需求與 SPEC。
  • BetLogics 的來源設定、Soak／Review／Early Settlement 規則，仍需逐項對照 InSports 的 03、04、07、12；沿用入口不等於沿用業務規則。
  • 07、08 的骨架與 09 的概念草稿補完後，再繪製下注到派彩的操作頁。此處只列出所需能力，不自行決定尚未定案的操作。
