共用導覽框架 · 第一階段單場比賽與冠軍盤主選單 · 主內容區留白 · 2026-11-03

比對 BetLogics 的既有入口與層級，包含單場比賽與冠軍盤。此模式只供 UI 參考，業務規則與交付範圍以 InSports PRD 及本次決定為準。

第一階段涵蓋單場比賽與冠軍盤的建立、賽程、識別、屬性、生命週期、對應及人工審核。詳細賽況、賠率、賽果與結算入口留在其他模式。Planned 表示尚未繪製；Feed Monitor 保留既有規劃位置，Scope TBD 表示本階段歸屬尚未決定。

完整流程另呈現詳細賽況、賠率、賽果、結算，以及注單、提前兌現、風控、經銷商設定、報表與匯率入口。此模式不擴大第一階段交付範圍，詳細業務規則仍以各 PRD 為準。

範圍更新（2026-11-03）：現行範圍已取代先前的「冠軍盤另行規劃」及含賠率、盤口結算結果與對外供應的較廣第一階段定義。冠軍盤已納入第一階段；PRD 04 原先暫緩的冠軍盤識別、對應及生命週期細節仍待補齊，不能以本次範圍視為規則已定案。生命週期狀態不因詳細賽況與結算延後而排除。

現有頁面的分工與來源依據

依 BetLogics 的主選單與頁面導覽核對。這份草稿核對的是頁面與導覽，不代表已驗證正式環境的功能完整性。

目前四個 Catalog 頁面、Matches 的 Schedule／Mapping／Match Review、Outrights 的 Schedule／Mapping，以及 Provider 的兩種 Schedule 均連到本次草稿；其餘為位置示意，不代表功能已完成。Provider › Betting 在現有模式保留作為對照，它是系統管理者的驗證下注工具，並非玩家注單清單。驗證外部下注不屬於本次 InSports 賽事產線；取得資料帳號只用於讀取資料（R03-04），因此已採用的第一階段模式移除它。單場比賽與冠軍盤皆屬第一階段；Outrights › Schedule／Mapping 及 Provider › Outrights › Schedule 已有草稿；缺少規則的功能保留待確認，不因頁面存在而視為定案。BetLogics 的來源冠軍盤入口原名為 Events，InSports 依本次決定稱為 Schedule。預設顯示本次第一階段選單，其他模式保留後續工作與 UI 對照。

已採用方案與後續功能規劃

現行範圍（2026-11-03）：第一階段由來源資料建立單場比賽與冠軍盤的統一紀錄，維護賽程、識別、屬性、生命週期狀態、對應與人工審核。詳細賽況、賠率、賽果與結算延後。此決定已取代本稿先前「冠軍盤另行規劃」及「賽事資料、賠率與盤口結算結果，直到交付給使用者」的第一階段定義。仍沿用既有入口與次頁，不另建 Sources、Accounts、Mapping Tables 主選單；驗證下注入口仍排除。Feed Monitor 保留既有規劃位置，本次未決定其階段歸屬或新增功能。

新增與不新增的決定

項目建議原因與完成條件
Feed Monitor保留既有規劃入口，標示 Planned 與 Scope TBD；本次未決定階段歸屬。先前規劃的功能需求為依客戶與資料類別查看 API／串流的供應狀態、最後送出時間與資料版本、延遲、錯誤、斷線及補同步情形，並連回相關賽事或 Feed Tenant。伺服器成功送出與客戶確認收到要分開；沒有客戶確認機制時不得宣稱已收到。實際可觀測欄位與門檻待定。
Pipeline沿用 Connectors 的次頁。頁面已存在。若值班使用頻率高，可提升為主選單捷徑；這是導覽調整，不是新能力。
Dashboard / Attention補齊既有頁面與摘要資料。Dashboard 目前是畫面骨架；主選單 Attention 的數量與等待時間仍為固定範例。應接上真實的處理狀態與頁面捷徑，避免再建重複的總覽或審核入口。
Audit Log可選改進，暫不新增主選單。已有每位使用者的 Activity 與業務紀錄。若事故追查常需跨使用者、賽事或設定搜尋，再於 Users & Permissions 增加共用檢索入口；底層稽核不是從零開始。
Sources / Accounts / Mapping Tables不另建獨立主入口。沿用 Provider Settings、Commentary 與既有對應頁。InSports 規則有差異時，調整其頁內內容，避免兩個入口管理同一件事。
Provider › BettingInSports 第一階段模式移除。它驗證供應商下注，不是 InSports 的玩家下注流程；取得資料帳號不得下注（03 的 R03-04）。

本稿呈現導覽方案與各階段分工。Feed Monitor 的功能頁、資料介面及階段歸屬，以及 Dashboard／Attention 的真實數據串接，仍待後續規劃；保留入口不表示本次新增交付。業務規則以 InSports PRD 為準。

完整投注流程規劃：玩家下注到派彩

「完整投注流程（規劃）」模式已列出下列入口，供整體導覽檢視。接受狀態與追查放在 Bet List；Monitoring 同時涵蓋監控參數、趨勢與曝險；Reports 內提供投注額與 GGR 檢視。功能頁在對應 PRD 明確後實作。

建議群組與入口要補上的工作需求依據與狀態
Bet Operations › Bet List查看真實玩家的注單、等待／確認／拒絕狀態與原因，從同一筆注單追查接受流程及錢包扣款邊界；不另設重複的 Acceptance 主入口。06：R06-18、R06-19、R06-20；頁面分工為建議。
Settlement › Bet Settlements / Payout Exceptions由投注項結果追到注單結算、取消、重新結算，以及派彩失敗或扣回的注單狀態；實際錢包入帳仍由整合端負責。07 的目的與範圍；規則仍是骨架，不能先指定重試或強制入帳操作。
Risk › Monitoring / Review Queue / Rules查看監控參數、趨勢與曝險，處理警示與人工佇列，維護基本條件與觸發條件。09 概念草稿；R06-10、R06-17 提供限額與人工標記的邊界。
Distributors › Settings經銷商的偏好、價格、模板、開關與繼承／覆寫。此入口依經銷商角色的權限提供，並不授予 Ops 任意修改所有經銷商設定的權限；Feed Tenants 仍負責 API 客戶權限。10：R10-01 至 R10-04；12：R12-08。
Reports / Settings › Exchange Rates投注額、GGR 與經銷商層級報表；依營業日查看及覆寫匯率。11 的目的與範圍、R11-01；報表詳細欄位待撰寫。
Bet Operations › Cash Out提供提前兌現紀錄與失敗狀態的入口；注單可否提前兌現依玩法設定與 08 的規則決定。詳細規則待補完，不預先加入人工強制兌現操作。08 的目的與範圍；規則仍是骨架。
