來源設定・賽程來源（Fixture Sources）

日期：2026-11-06 · 選單：Settings › Provider Settings › Fixture Sources · 對應 PRD：03 資料來源與連接器、04 賽事資料與對應 · 畫面索引

服務的工作Ops 設定每個運動的賽程來源，以及哪些來源具備完整賽程能力；更換來源前確認影響的範圍。
不在本頁
  • 各類資料的使用開關與取得狀態：Data Usage（R03-05、R03-13）。整個連接器的暫停、恢復與影響：Connectors（R03-07）；個別取得途徑與帳號維護另屬串接維運（R03-04）。
  • 逐場指定建立者、競賽審核與賽事對應操作：04 的 R04-02、R04-05、R04-08；本頁只設定運動層的預設來源。
  • 賠率、賽況與賽果的來源角色及競賽覆寫：R04-02。經銷商無法查看或設定來源。
  • 虛擬競賽的來源另行指定；方式尚待決定，不套用此處的運動預設（R04-20）。

本頁是需求示意，不約束版面、元件或資料模型。來源名稱、能力設定、運動與數字均為範例；能力設定不是對各供應商實際服務的判定。畫面只畫主內容區，側邊主選單見共用版面。

功能清單

#功能對應規則畫面
1以來源與運動矩陣查看預設賽程來源；每個運動恰好一個，沒有競賽覆寫R04-02；R01-24畫面 1
2在矩陣內更換預設來源，於表格下方填原因並儲存或放棄變更R04-05；04 第 5 節；非功能需求與稽核畫面 1、畫面 2
3由 Ops 設定完整賽程能力；沒有能力設定的來源不能被指定R03-05；R04-01、R04-02、R04-05畫面 1、畫面 3
4區分來源指定、資料使用狀態與取得途徑；中斷不自動改換來源R03-01、R03-05、R03-13；R04-02畫面 1
5唯讀查看目錄運動與各來源的運動代碼R03-08；R04-03畫面 4

  1. 1Search 依運動名稱篩選；Esports 的 OFF 只列一般運動，ON 只列電子競技，每個遊戲各一欄，沒有合併的 Esports 運動。本例依目前 PRD 目錄列出 27 個一般運動；數量隨篩選結果改變（R01-24）。篩選不改變賽程來源設定。
  2. 2每列一個來源、每欄一個運動；來源欄固定，運動欄可橫向捲動。每個運動恰好選一個來源，選另一個會取代原選擇，沒有競賽層覆寫（R04-02）。綠色 Source 為目前畫面選擇，Select 為可選來源；「—」表示未設定完整賽程能力，不能選取。RunningBall 與 BetGenius 分別保留 via insportlive（R03-01、R03-05）。本例 Saba 負責足球與網球，Sbobet 負責其餘 25 個一般運動；點 Sbobet 的足球格查看畫面 2。
  3. 3原因與按鈕放在矩陣下方，不另開換來源視窗。選擇後先保留於頁面，填寫原因才可按 Save fixture sources；沒有變更時 Save／Discard 不可用。Discard changes 放棄尚未儲存的選擇，儲存時記錄所有已修改運動、前後值、操作者、時間與原因（R04-02；非功能需求與稽核）。
  4. 4變更預設只影響之後建立的賽事；既有賽事由原建立者負責到結束。新來源列出的比賽仍先與既有紀錄比對，新競賽依原規則進待處理清單；不因改設定搬動既有賽事（R04-02、R04-05）。虛擬競賽另行指定，不使用此預設（R04-20）。
  5. 5Full fixture capability 另開畫面 3，不佔用運動矩陣的欄位。完整賽程能力由 Ops 設定，與資料是否正常取得、是否被選為來源分開；各類資料的狀態在 Data Usage（R03-05）。中斷不自動換來源，已指定來源的 Match 資料不能停用（R03-13、R04-02）。本例 Sofascore 也設為有完整賽程能力，與另外四個可選來源一樣顯示 Select；這些值只用於示意。
  6. 6右上角 Sport Codes 開啟畫面 4，唯讀對照目錄運動與來源運動代碼，不新增對應操作，也不變更本頁的賽程來源（R03-08、R04-03）。

待確認事項

  1. 虛擬競賽的來源指定方式：R04-20 明確留待虛擬資料來源決定後補上。建議確認後另畫指定畫面，本頁維持運動層的預設。
  2. 來源已有未結束賽事時，撤銷完整賽程能力的生效方式尚未明定。建議保留既有建立者責任，只停止新的指定；本頁不畫撤銷後轉移或中止既有賽事。仍被選為運動預設時，先更換預設再撤銷。
