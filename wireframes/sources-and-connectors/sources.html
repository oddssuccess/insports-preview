來源（Source）

狀態：草稿（示意） · 所屬：資料來源與連接器後台 wireframe · 對應 PRD：03 資料來源與連接器

服務的工作Ops 查看每個來源的四類資料目前能否取得、各來源有哪些取得途徑與備援、最近的狀態變化；依「來源 + 資料類別」停用或啟用；啟用新串接的來源與途徑
對應規則R03-01（資料以原始來源計）、R03-02（途徑互為備援）、R03-05（依資料類別判定狀態）、R03-06（中斷與恢復）、R03-07（中斷與停用）、R03-12（新來源由人工啟用）、R03-13（控制只有兩種）、R03-14（後台顯示）
不在本畫面新增或刪除來源與途徑（工程以設定建立）；連接器的暫停（見 連接器）；帳號（見 帳號）；來源角色與對應（見 04）；中斷或停用時盤口如何處理（見 04、05）

本頁是需求示意，用來說明畫面要提供哪些資訊與操作，不約束版面、元件或資料模型（見 PRD 與 SPEC 的分工）。畫面中的來源、帳號與數字都是範例。

  1. 1「Has interrupted」列出任一類資料中斷的來源，「Has disabled」列出任一類資料停用的來源（含連接器暫停與尚未啟用）。入口站台與轉送商不是來源，不在本清單（R03-01）；它們在連接器頁。
  2. 2可用途徑數／已啟用的途徑數，尚未啟用的途徑不計入（例如來源 C 的入口站台 Delta）。部分途徑失效只減少備援，來源仍為正常（R03-06），例如來源 C 的三條途徑只剩一條可用，但賠率仍正常。途徑的明細在詳情頁。
  3. 3四類資料與 04 的 R04-01 相同：賽程（含參賽方與冠軍盤名單）、賠率、賽況、賽果。賽程指能單獨成立的完整賽事清單；只隨賠率附帶的賽事資料不算，所以來源 D 有賠率，賽程仍是「—」。每格一個狀態：正常、中斷、停用、—（來源不提供）。狀態由系統判定，正常須有正面證據：收到有效內容，或對探測有有效回應；連線存在、只有心跳、來源靜默都不算（R03-05）。
  4. 4中斷顯示持續時間與原因（R03-14）。中斷由系統判定、自動恢復，Ops 不能手動恢復；恢復條件比中斷嚴格，時間數值見非功能需求（R03-06）。來源 C 的賽果只經直接輪詢取得，該途徑因速率限制失效，沒有其他途徑，所以賽果中斷；賠率經入口站台 Beta 仍可用，所以正常。
  5. 5停用一律標明原因（R03-07）：人工（依來源與類別停用，顯示操作者與日期）、連接器暫停（顯示哪個連接器）、尚未啟用。停用立即生效，人工解除後改由系統判定。整列淡色表示該來源所有提供的類別都停用，仍可查詢。
  6. 6新串接的來源在工程以設定建立後出現在清單，啟用前為停用（R03-12）。「Enable」開啟畫面 3，不需要試運轉。沒有新增與刪除。

  1. 1每類資料一列。「Last valid content」是 InSports 收到的時間（R03-08），供 Ops 判斷資料多久沒更新；資料延遲不影響狀態，只要持續收到有效內容即為正常（R03-05）。
  2. 2「Disable」是 R03-13 的第二種控制，開啟畫面 3；停用後該類資料不用於任何判定，仍可讀取供後台查看；其他類不受影響。運動的賽程來源的賽程沒有停用按鈕，只能在來源角色更換（04 的 R04-02）；被人工指定為建立者、還有未結束賽事的來源，其賽程的停用按鈕不可按並說明原因（範例中的來源 C，04 的 R04-05）。停用中的類別顯示「Enable」。中斷沒有手動恢復的按鈕（R03-06）。
  3. 3一個來源可以有多條途徑，每條途徑提供該來源的一類或多類資料，途徑之間互為備援（R03-02）。一類資料沒有任何可用途徑才算中斷（R03-06）：賽果只有「Direct」一條途徑，失效即中斷；賽程、賠率、賽況還有乙可用，仍為正常。
  4. 4途徑狀態：可用、失效（顯示持續時間與原因，含維護的影響範圍：整個入口站台，或某來源在某入口站台的入口）、連接器暫停、帳號停用、尚未啟用。失效由系統判定；暫停與停用由人工在連接器頁與帳號頁操作。
  5. 5新串接的途徑啟用前不可用（尚未啟用），不影響這個來源其他途徑與各類資料的狀態；由 Ops 在此啟用（R03-12）。沒有逐一途徑停用：要使途徑失效，只能停用它的帳號或暫停它的連接器（見本頁待確認第 1 項）。
  6. 6系統判定的變化與人工的變更都在同一份紀錄，人工變更記錄由誰、何時、原因（R03-13、非功能需求）。

待確認事項

  1. 是否需要逐一途徑停用。目前畫面只有帳號停用與連接器暫停會使途徑失效，與 R03-13「控制只有兩種」一致。
  2. 中斷的持續時間從何時起算：最後一次收到有效內容（上例 11:58），或系統判定中斷的時間（12:03）。畫面暫以判定時間起算。
