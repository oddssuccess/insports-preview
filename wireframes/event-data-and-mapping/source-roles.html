來源角色（Source Role）

狀態：草稿（示意） · 所屬：賽事資料與對應後台 wireframe · 對應 PRD：04 賽事資料與對應

服務的工作Ops 查看與設定每個運動的來源角色：賽程來源（每個運動恰好一個，不以競賽覆寫）；賠率來源、賽況來源（含訊號形式與優先順序）、賽果來源以運動設預設、以競賽覆寫；處理運動的賽程來源列出的新競賽
對應規則R04-01（四類資料與角色）、R04-02（角色由 InSports 設定；賽程來源只在運動層；其餘角色運動預設、競賽覆寫；使用中的賽況來源依固定順序）、R04-05（建立者）、R04-20（虛擬競賽的賽程來源）、第 5 節「更換某運動的賽程來源」
不在本畫面來源本身的狀態、途徑與帳號（見 來源）；人工指定建立者（見 賽事對應畫面 5）；某來源某場賽事的賠率因矛盾不採用（R04-17，下一批）；門檻數與最少來源數（見 門檻設定）

本頁是需求示意，用來說明畫面要提供哪些資訊與操作，不約束版面、元件或資料模型（見 PRD 與 SPEC 的分工）。畫面中的來源、競賽與數字都是範例。

  1. 1表格第一列永遠是所選運動的預設；其下是競賽。預設顯示有覆寫的競賽，切到「全部競賽」才列出沿用預設的競賽（淡色）。賠率、賽況、賽果三種角色是運動預設加競賽覆寫，不以計分項目指定（R04-02）。這些覆寫掛在統一競賽上，不需要來源的競賽對應。
  2. 2賽程來源每個運動恰好一個，不以競賽覆寫，所以不在表格裡（R04-02）。它沒列出的個別比賽，由 Ops 在賽事對應逐場指定其他來源為建立者（R04-05）。虛擬競賽的賽程來源另行指定，方式待 03 決定（R04-20）。「更換…」開啟畫面 3。
  3. 3賠率來源、賽況來源、賽果來源各一個以上。某來源某一項資料不可靠時，Ops 在該競賽把它整個拿掉（R04-02）。來源提供某類資料不代表擔任該角色：只能從提供該類資料的來源中挑。
  4. 4賽況來源有順序：有訊號的最高順位者即為使用中的賽況來源，滾球訊號只取它（R04-21）；滾球比分則用全部賽況來源（R04-14）。訊號形式（事件形式、封盤形式）是來源的屬性，唯讀，兩種形式排在同一個順序裡。Ops 不逐場指定，也不在比賽中途改用另一個來源（R04-22）。
