來源角色（Source Role）

狀態：草稿（示意） · 所屬：賽事資料與對應後台 wireframe · 對應 PRD：04 賽事資料與對應

服務的工作Ops 查看與設定每個運動的來源角色：賽程來源（每個運動恰好一個，不以競賽覆寫）；賠率來源、賽況來源（含訊號形式與優先順序）、賽果來源以運動設預設、以競賽覆寫；處理運動的賽程來源列出的新競賽
對應規則R04-01（四類資料與角色）、R04-02（角色由 InSports 設定；賽程來源只在運動層；其餘角色運動預設、競賽覆寫；使用中的賽況來源依固定順序）、R04-05（建立者）、R04-20（虛擬競賽的賽程來源）、第 5 節「更換某運動的賽程來源」
不在本畫面來源本身的狀態、途徑與帳號（見 來源）；人工指定建立者（見 賽事對應畫面 5）；某來源某場賽事的賠率因矛盾不採用（R04-17，下一批）；門檻數與最少來源數（InSports 固定，R04-14）

本頁是需求示意，用來說明畫面要提供哪些資訊與操作，不約束版面、元件或資料模型（見 PRD 與 SPEC 的分工）。畫面中的來源、競賽與數字都是範例。

Change soccer fixture source · Source A → Source C✕

A change is a planned migration, e.g. between seasons, not an emergency measure when a source is interrupted 1.

System checks 2

  • Source C provides fixtures (R04-01)
  • Source C competitors: 1,184 established, 37 not established (list). A non-established competitor gets a temporary separate record in events C creates later, to be merged manually once established (R04-04)
  • Source C's 214 tournaments go to “New tournaments”, where Ops creates them or maps them to existing ones (R04-02)
  • 58 future matches listed by A but not by C: not created after the change unless a creator is assigned per match (R04-05)
  • The 3,402 events already created are still updated by Source A until they end; matches C lists that A already created map to the existing records, no new ones (section 5)
