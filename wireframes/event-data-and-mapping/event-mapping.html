服務的工作Ops 查看各來源列出的賽事各自對應到哪一筆統一賽事、依據什麼、方向為何；處理有多個候選或等待證據的對應（人工確認）；更正錯誤的對應；合併疑似重複的統一紀錄；對運動的賽程來源沒列出的個別比賽，人工指定建立者
對應規則R04-04 至 R04-07（統一紀錄只由建立者建立、人工指定建立者、系統不合併）、R04-08（確認依據與確立的累積）、R04-09（多個候選不猜）、R04-10（更正只能人工）、R04-19（覆核）、R04-20（虛擬不與真實對應）
不在本畫面運動的賽程來源與新競賽（見 來源角色）；待取消與候選（見 待取消與待腰斬）；玩法對應（R04-11，下一批）；顯示名稱與多語系（見 10）

本頁是需求示意，用來說明畫面要提供哪些資訊與操作，不約束版面、元件或資料模型（見 PRD 與 SPEC 的分工）。畫面中的來源、賽事與數字都是範例；各來源對同一支隊伍的寫法刻意不同。

  2. 2未對應：尚無確認依據，也沒有候選。等待證據：有一個以上候選，但依據不足（例如兩個方向都說得通、兩個候選都符合），系統不猜（R04-09）；這些列入待處理的「Mapping candidates」頁籤。已對應：有確認依據。已結束的賽事保留多久才不顯示，見待確認。
  3. 3可只看部分來源。來源以代稱顯示，不標示類型；各來源提供哪些資料見來源頁。
  4. 4來源下方是運動。第三欄是賽事狀態點：○ 未開始、● 進行中；來源已撤回該賽事時另加標示但不隱藏。第四欄 ⇄ 標示該來源的主客順序與統一紀錄相反（反向）。
  5. 5主隊在上、客隊在下，一律顯示來源自己的寫法，不顯示統一名稱，提醒名稱相似不是依據（R04-08）。右側徽章：已對應時顯示該統一賽事目前有幾個來源（含建立者）；未對應時顯示首次出現至今的時間。
  6. 6最後一欄只有兩種記號：✓ N 是這個來源賽事與其他來源之間已確認的對應數；候選 N 是尚未確認的候選數（兩個方向都說得通、多個候選都符合等，系統不猜，R04-09）。依據、方向與等待原因在右側面板與對應明細，不在列上。
  7. 7標題用統一名稱，主客與參考名稱以建立者為準（R04-06）。選取左側任一列，面板顯示該列所屬的統一賽事，以及這場比賽的所有來源；左側同一場的其他列加淺色左邊線，候選列用虛線。
  8. 8這場已有對應的賠率來源，之後出現的賠率來源可依賠率一致（a）比對。若尚無已對應的賠率來源（例如只有不提供賠率的建立者列出），這行改寫「No mapped odds source yet; only competitor establishment, post-match matching or manual mapping」（R04-08）。
  9. 9建立者一列沒有解除操作（R04-05、R04-06）；建立者可能是運動的賽程來源，或被人工指定的來源。左側徽章的數字＝建立者＋已對應，與標題的「3 sources」一致。選取的列標「Selected」。
  10. 10候選中：系統找到候選但依據不足，不猜，期間該來源的資料不用於該賽事（R04-09）。另有其他候選時寫出來。「Map manually…」開啟畫面 3，已帶入這筆統一賽事。
  11. 11可能相關：尚未對應、也不是候選的來源賽事，沿用畫面 3 的方式依開賽時間與競賽排序，方便 Ops 主動處理。名稱相似不是依據（R04-08）。這是新增的清單，可以不做（見待確認）。
  12. 12操作跟著各列：「Details」開啟畫面 2；「Unmap…」須填原因，由另一人覆核後才生效（R04-10、R04-19）。解除對應會使該賽事的狀態與賽果依剩餘來源重新整理，受影響的注單由 07 處理。
  13. 13選取有多個候選的列，面板先顯示排序第一的候選，可切換；選取沒有候選的未對應列，面板頂端寫「is not mapped」，可切換排序在前的統一賽事；都不是同一場時，按「Assign as creator…」開啟畫面 5（R04-05）。
